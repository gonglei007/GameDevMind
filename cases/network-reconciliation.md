# 网络同步案例复核：MOBA 角色回弹

> 原稿描述了海外高延迟下的移动回弹，但未附构建、原始日志、故障注入配置或用户统计。本次将其作为诊断教学案例复核，不把历史叙述当作已证实的线上事故报告。

## 适用条件

适用于服务器权威、本地玩家预测且可保存/重放输入的移动模型。必须有独立快照序号、连续已处理输入确认、可重建的状态和明确的输入有效期。远端实体的快照插值、确定性 lockstep 和本地玩家校正不能混为一个算法。

## 症状与待验证假设

移动后收到权威状态发生视觉跳变，可能涉及输入时点错配、预测规则不一致、丢包/重传、排队、服务器 tick 积压或渲染层校正。高 RTT 可能放大差异，但不能只凭客户端当前位置与旧权威位置的距离判定预测错误。

原稿中“服务器提前收到输入，所以客户端仍沿旧方向走”的因果不成立：本地输入首先在客户端产生。应沿输入生成 → 发送 → 服务接收/排队 → 执行 → 快照发送 → 客户端收到的时序定位。不同主机的时钟未经校准不能直接相减得到单向延迟。

| 要验证的假设 | 需要的记录 | 能得到什么结论 |
|------|------|------|
| 传输或排队变慢 | 双向 RTT/抖动、输入/快照号、重传与队列年龄 | 分清到达慢、执行慢和响应慢，不能只看处理函数耗时 |
| 预测规则不同 | 同一初始状态、同一输入序列、原 dt/tick、碰撞与技能状态 | 比较同一确认时点的状态误差 |
| 确认/重放错误 | 连续确认前缀、待确认队列、下一个输入号 | 是否回退序号、重复执行或错误丢弃历史 |
| 渲染平滑问题 | 校正后逻辑位置、渲染偏移与实际帧 dt | 区分逻辑错误和显示跳变，不用平滑遮蔽错误 |

原稿“0.7% 丢包率所以排除网络”“移动处理 p99 < 5ms 所以排除服务端”均缺少统计口径且证据不足；平均丢包率会掩盖突发，处理耗时也不包含全部排队。

## 方案取舍

### 输入确认与重放

客户端每个模拟 tick 保存输入序号、方向/按钮及原始 dt 或固定 tick，立即预测并发送。正常 tick 只推进一次，不能反复在已经预测过的当前位置重放整队列。

收到新权威快照时：

1. 验证会话代次、快照新旧、连续确认输入号与权威状态；拒绝未来确认，忽略旧快照。
2. 移除已确认前缀，采用对应的权威逻辑状态。
3. 从权威状态重放剩余输入，各自使用原 dt/tick 和相同规则；下一个输入号保持单调。
4. 输入缺口或积压超过上限进入显式恢复流程，不能静默删未确认输入后假装仍可准确校正。

这是状态对齐，不意味着立即显示旧权威位置。命中特效、音效、扣费等副作用要抑制重复或与预测事件身份关联；线性位置教学无法证明完整技能/物理状态可重放。[输入确认与校正原理](https://www.gabrielgambetta.com/client-side-prediction-server-reconciliation.html)

### 逻辑与显示分离

逻辑状态按有效权威状态与未确认输入重建；显示层可保留校正前视觉位置相对新逻辑位置的偏移，再随时间衰减。若采用指数衰减，可用 `offset *= exp(-render_dt / tau)`，其中 tau > 0 为待实测时间常数。固定“每帧 Lerp 0.3”在不同帧率下有不同衰减速度。

这只是显示策略之一，仍需测镜头、碰撞和瞄准体验。传送、复活、大误差或安全校验可以直接重置显示；“硬设必错、所有校正必须平滑”不成立。显示阈值只能控制视觉处理，不能在距离小于 0.5 米时直接 return，跳过输入确认与权威逻辑采用。

## 不适用场景

| 不应直接套用 | 原因 | 替代方向 |
|------|------|------|
| 遥控实体持续按本地输入重放 | 本机没有其完整输入/规则状态 | 快照插值、有限外推和过期恢复 |
| 跨平台物理未经确定性核对 | 同一输入也可能产生不同状态 | 共享可预测子集、完整校正状态与误差预算 |
| 未实现可靠输入前缀的原始 UDP | 缺号使“已确认至 N”含义不成立 | 输入冗余/重传、去重、过期与缺口恢复协议 |
| 重放全部技能外部副作用 | 可能重复音效、伤害、道具消耗 | 明确预测事件身份和权威效果边界 |
| 用显示平滑修复持续逻辑发散 | 只隐藏现象，还会增加显示延迟 | 先修复时点、规则、确认和队列错误 |

## 验证方法与仓库结果边界

[Python 协议示例](../code/artile-sample-code/02-technical/05-networking/) 给出本地二维输入模型：原 dt 重放、停止输入、单调输入号、重复输入去重、旧/未来快照、积压超限显式失败。[真实 Socket 回环](../code/artile-sample-code/01-foundation/06-os-network/) 另验证传输分帧与 UDP 乱序/重复，不是该模型已经通过真实弱网测试。[C++ 同步模型](../code/gamedevmind/2.技术能力/2.2.1.网络与通信/network_sync/) 有独立 CTest/sanitizers 回归。

项目验收还需固定构建、平台、初始状态、输入录像和故障脚本：双向分别注入延迟/抖动、突发丢失、乱序/重复、断网/切网，覆盖变向、停止、碰撞、位移技能与恢复。测同确认时点误差、最终收敛、输入年龄、队列上限、逻辑/视觉误差、重复副作用和玩家体验。先声明预算再判定，不将所有项目固定为“至少 200ms”一个档位。

原稿的回弹次数 15–18→2–3、最大距离、主观评分与客诉下降 85% 均没有可复现记录，本次撤下效果对比。当前可复核的是仓库断言与 CI；不能据此声称线上体验、物理一致性或反作弊已达标。
