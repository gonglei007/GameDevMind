## 用户与帐号系统
<p>
用户与帐号系统负责建立玩家身份、游戏角色和产品服务之间的稳定关系，为登录、跨端、封禁、客服和后续商业化提供统一身份基础。
</p>

**关键词:**<br/>
*用户系统,帐号系统,登录,游客帐号,第三方登录,身份验证,角色管理,实名认证,AI Coding*

**标签:**<br/>
*等级: 中级, 阶段: 开发|运营, 分类: 研发能力, 角色: 客户端开发|服务端开发|管理*

## 身份模型

```text
自然人/设备 -> 平台帐号 -> 游戏帐号 -> 区服角色 -> 角色数据
```

| 对象 | 作用 |
|------|------|
| 平台帐号 | 对接 Apple、Google、Steam、微信等平台身份 |
| 游戏帐号 | 作为游戏内部稳定的用户主键，隔离外部平台变化 |
| 区服角色 | 表示玩家在具体区服或世界中的游戏身份 |
| 设备身份 | 支持游客登录、风险识别和设备迁移，不应替代正式帐号 |

## 登录方式

| 登录方式 | 适用场景 | 关键问题 |
|----------|----------|----------|
| 游客登录 | 降低首次体验门槛 | 卸载或换机丢失；需要绑定引导和恢复机制 |
| 手机/邮箱 | 自有帐号体系 | 验证码滥用、密码找回、地区法规 |
| 第三方登录 | 使用平台已有身份 | Token 校验、平台解绑、跨平台合并 |
| 实名认证 | 受监管地区 | 最小化存储敏感信息，保留合规审计记录 |

## 角色与区服

需要明确一个帐号是否允许多角色、多区服角色如何索引、合服后如何处理重名，以及角色删除、恢复和迁移规则。身份关系应使用稳定 ID，不要把昵称、手机号或第三方展示名作为业务主键。

## 帐号运营能力

| 能力 | 要点 |
|------|------|
| 查询 | 支持帐号、角色、订单、设备和第三方身份等多维检索 |
| 封禁与解封 | 区分帐号、角色、设备和 IP 范围，要求审批和审计 |
| 绑定与解绑 | 防止帐号盗取，关键操作要求二次验证 |
| 合并与迁移 | 明确数据冲突和回滚策略，不直接覆盖原数据 |
| 客服恢复 | 建立身份核验规则，保留完整操作日志 |

## 安全与合规

| 风险 | 解决方向 |
|------|----------|
| 凭证泄漏 | TLS；短期 Token；刷新机制；服务端校验；密钥轮换 |
| 撞库和暴力登录 | 限流、验证码、设备风险识别、异常告警 |
| 帐号盗取 | 二次验证、异地登录提醒、敏感操作冷却期 |
| 隐私风险 | 数据最小化、用途限制、删除与导出能力、访问审计 |

| 类型 | AI Coding 指南 |
|------|----------------|
| **交互提示** | 说明平台、地区、游客模式、多区服和合规要求 |
| **方法** | 先定义身份模型和权威 ID，再设计登录、绑定、迁移和运营后台 |
| **应用** | 登录服务、Token 体系、帐号绑定、合服迁移、封禁审计 |
| **提示词范例** | 「手游需游客、Apple、Google 登录，支持多区服角色和游客绑定；请设计身份数据模型、Token 流程、绑定冲突处理与审计日志」 |
