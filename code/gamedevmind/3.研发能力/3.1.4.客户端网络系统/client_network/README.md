# 客户端网络生命周期模型

配套 [客户端网络系统](../../../../../mds/3.研发能力/3.1.4.客户端网络系统.md)。Python 3.11+ 标准库，使用显式单调时间和人工事件，无第三方依赖。

## 适用条件与实现契约

模型用来验证客户端编排，不实现实际 Socket、DNS、TLS、Unity 或具体网络库 API：

- 顺序为 Connecting → Authenticating → Restoring → Ready；业务请求只在 Ready 准入。
- 单次恢复活动共享 30 秒总预算，每阶段最多 5 秒，至多 4 次连接尝试。失败后使用 full jitter，随机范围上限为 `min(8, 0.5 * 2**min(attempts, 5))` 秒；这些是教学参数，不能用作项目通用推荐。
- 旧事件按连接代次隔离；适配器必须绑定原管理器实例，不能把旧实例回包转交新帐号实例。认证/升级拒绝进入 Blocked；不自动重试或绕过升级。
- 请求 ID 单调递增且不复用。模型假定准入即交给传输，取消、超时、断开、关闭均只交付一次 `unknown`；不证明服务端未执行，不自动重发。
- `operation_key` 由业务调用方保留并随结果返回，便于查询未知结果；模型不生成持久业务 ID、不发送/校验它，也不实现服务端幂等。
- `response` 结果只表示匹配响应到达；调用方仍须解码、判断业务成功/拒绝与权威版本，不能据此直接发奖。
- 默认请求与未消费结果合计至多 16 个：准入为终态预留容量；消费结果后才释放容量。邮箱至多 32 条事件，每条 body 至多 4096 字节。每次 pump / drain 默认最多交付 8 条，生产还需每帧时间/解码预算。
- 只有 `post(Event)` 可由工作线程调用；其他方法均由创建实例的拥有者线程执行。事件冻结且 body 为 bytes，避免跨线程共享可变数据。没有真实 Unity 回调验证。

## 适配与不适用场景

事件的身份、协议、响应匹配及控制消息来源应由安全传输适配器验证。`tick(now)` 负责时间推进；调用者用 `time.monotonic()` 或游戏内可靠单调时钟供时。边界时刻先判超时再交付排队事件，所以到达截止时间的结果按未知处理。

`post` 邮箱满时显式抛出 BufferError，适配器必须停止准入/读取并通过受控故障路径通知拥有者；不可在工作线程无限重试或静默吞错。本模型不提供完整 IO 关闭/故障通道。`close` 只关闭编排状态，实际适配器还必须取消任务、关闭连接、解除订阅，旧 UI 也必须退订。关闭后实例不再 start，帐号切换创建新实例并保持适配器引用隔离。

不适用于直接上线、取消后自动创建新订单、认证拒绝无限重试、无界离线写队列或用 UI 遮罩代替服务器幂等。真实认证/恢复响应、业务错误码、订阅增量恢复、前后台和切网都需项目实现。

```bash

```

回归覆盖恢复门禁、旧回调、截止边界、重试上限/总预算、永久拒绝、取消/超时/重复响应、顺序关联、预留结果容量、关闭与真实工作线程邮箱/拥有者检查。CI 在 Windows/Linux 阻断执行。
