# MySQL 事务契约示例

对应 [数据库](../../../../../mds/2.技术能力/2.2.2.数据库.md)。示例将一笔游戏内计数转移与请求记录在同一 InnoDB 事务中提交，用真实连接验证并发和读视图。

## 业务与失败契约

- 账户 ID 为唯一正整数，余额是非负 int64；转移量为正整数，不允许同账户转移，检查收方溢出。
- Request.ID 是作用域内唯一的 1～64 字节请求身份，以 VARBINARY 主键比较；同 ID/同参数返回已执行，同 ID/不同参数拒绝。数据库记录保留期必须覆盖重试窗口，本例不清理记录。
- INSERT 请求身份、按账户主键升序逐一 FOR UPDATE、检查并更新两行、COMMIT 位于同一事务。获取锁顺序不依赖查询 ORDER BY；失败自动回滚，不留占位记录或单边效果。
- 重复 INSERT 等待原事务结束后，READ COMMITTED 下读取已提交参数。示例只识别此表唯一主键的重复键错误，不把任意 SQL 错误当成重复成功。
- 提交确认丢失时结果可能未知，调用者必须保留同一 ID 查询/重试，不生成新 ID 重新执行。测试未模拟网络在 COMMIT 确认时断开，不能声称已验证所有不确定提交故障。
- 余额变化与请求行的原子性仅覆盖同一个数据库。没有鉴权、租户/区服隔离、支付验单、外部发货、outbox、故障切换、自动死锁重试或生产 schema 迁移。

该实现不是可直接上线的交易服务。真实产品需增加权限、业务限额、幂等身份来源、保留策略、观测和有界重试；其他调用链必须遵守同样的锁定约束。

## 验证与运行

Go 1.27.2 或兼容版本，依赖与校验文件已锁定。进入本目录：

```bash
go mod verify
go test -v -count=1 -timeout=60s ./...
```

没有 MySQL 环境变量时，真实数据库回归明确 SKIP，只能说明代码编译与请求边界测试通过。真实回归只能配置一次性 **database_regression** 数据库；测试验证库名后创建唯一表和新测试记录，不运行 DROP、DELETE、TRUNCATE 或旧表迁移。不要使用生产凭据。

```bash
export DATABASE_CONTRACT_MYSQL_DSN='root:fixture-only@tcp(127.0.0.1:3306)/database_regression?timeout=2s&readTimeout=2s&writeTimeout=2s'
export REQUIRE_DATABASE_INTEGRATION=1
go test -race -v -count=1 -timeout=90s ./...
```

PowerShell 用 `$env:变量名='值'` 设置变量。CI 自带独立 MySQL 8.0 服务并设置 REQUIRE，缺配置直接失败。夹具数据随 CI 容器销毁；本地使用者自行管理其一次性服务。

实际断言包括：

1. 成功提交、同参数重复请求、不同参数冲突；余额不足、缺账户、收方溢出和已取消请求不留半份效果/占位。
2. 并发同 ID 只生效一次，不同 ID 的并发转移不丢更新，总量保持。
3. 受控时序下先读左账户，再由另一个事务提交转移，再读右账户：RC 两次语句可混用提交点，RR 普通一致性读保留同一视图；单条 SUM 查询仍观察完整总量。这是**已提交读偏差**示例，不是脏读。

Go race 检查客户端执行路径，不代替数据库隔离验证；数据库断言使用真实 InnoDB。测试不测生产执行计划、容量、复制延迟、日志刷盘/恢复或故障切换持久性，这些仍需按 [数据库：验证方法](../../../../../mds/2.技术能力/2.2.2.数据库.md#验证方法) 验收。
