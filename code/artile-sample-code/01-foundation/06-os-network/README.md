## 演示场景

| 场景 | 协议 | 说明 |
|------|------|------|
| **登录/交易/聊天** | TCP | 可靠传输，有序送达，每条消息有 ACK 确认 |
| **位置同步 (理想)** | UDP | 高频快照，无丢包时表现完美 |
| **位置同步 (真实)** | UDP + 30% 丢包 | 展示 UDP 尽力而为特性，丢包由应用层补偿 |

## 设计要点

- TCP 服务器使用 `accept` + `recv`/`sendall`，保证数据完整
- UDP 使用 `sendto`/`recvfrom`，无连接，无流控
- 位置同步使用 `struct.pack` 打包 `(seq, x, y, z)`，模拟游戏协议
- 丢包服务器主动丢弃 30% 的包，展示真实网络特征
- 多线程模拟客户端-服务端通信

## 要点

- TCP 适合必须可靠送达的场景（登录、交易、任务状态）
- UDP 适合高频实时同步（位置、射击、语音）
- 现代游戏引擎通常 TCP + UDP 混合，或在 UDP 上构建可靠层 (ENet/KCP)
- UDP 丢包不是 bug 是 feature —— 低延迟比绝对可靠更重要
